# PA3 Chrome extension bridge (macOS)

The extension uses PA3's persistent Qwen3-TTS model. Chrome plays the returned audio, preserving pause/resume, passage navigation, highlighting, and playback speed. There is no separate speech server or model environment.

Follow [the extension setup](../README.md#setup-on-macos) to load the extension and register the native host from the PA3 repository. The [PA3 narration API](../../README.md#local-narration) documents HTTP endpoints, authentication, and limits.

The bridge uses Python 3's standard library only. Chrome launches it on demand; it connects to PA3 on `127.0.0.1:65462` and reads `~/Library/Application Support/PA3/narration-token`. The token stays outside the extension and web pages. No localhost browser permissions or CORS exceptions are needed. If using a custom PA3 port, set `PA3_NARRATION_PORT` in Chrome's launch environment too.

The voice is PA3's American male (Iowa), VCTK p311. Speed is applied during browser playback. Pronunciations are managed in PA3 under Dictionaries… → Narration. The bridge forwards original paragraph text; PA3 applies its shared dictionary and pronunciation rules.

The extension sends the complete extracted source as one `output: stream, timing: words` job, up to 100,000 characters. Browser sentence ranges are for navigation only. PA3 applies the same text cleanup, dictionary, sentence splitting, and paragraph/list pauses as selected text and OCR. Each complete sentence is one Qwen request, without character-budget cuts. PA3 tops up trailing silence to the planned boundary pause. It returns mono float32 PCM after local recognition has supplied timing metadata. The bridge forwards `word_timings` unchanged as `wordTimings`, with job-relative audio seconds and original UTF-16 source ranges. The bridge polls every 50 ms, forwards only new PCM blocks, and sends an explicit passage-end event. Web Audio schedules adjacent blocks continuously, with no text splits or pauses between blocks. Pause, resume, replay, passage navigation and settings previews share the streaming player. Playback speed uses streaming waveform-similarity overlap/add to preserve pitch; 1× playback passes samples through unchanged. The browser uses recognized timings for a moving group of three source words inside a subtly highlighted paragraph; timings remain approximate. A starved or interrupted player shows “Buffering” and resumes from the same audio position when more audio or the audio device becomes available. Generation can still fall behind playback on a busy GPU.

The bridge validates PCM lengths and ordering and deletes each job after transfer. PA3 never plays these jobs itself. Closing the tab or stopping narration cancels only that connection's current job. Errors are logged and narration stops; there is no alternate speech engine. Downloads expire on PA3 after five minutes if a client disappears.

Each source uses one transport stream. The browser acknowledges it after playback or skip, and stopping cancels that source. Prefetch can prepare the next candidate independently. Pausing playback pauses audio; PA3 may continue generating the current source. Previous-sentence navigation seeks within retained audio using source offsets and recognized word timings. The shared per-page audio budget is 32 MiB for retained PCM and scheduled Web Audio copies (temporary transfer/processing allocations are additional). Exceeding this limit fails explicitly instead of growing without bound.

Validation commands and requirements are listed in [the extension development and tests](../README.md#development-and-tests). The root `make test` covers both the extension and PA3, including model-backed decoder compatibility. `make browser-test` checks real Chrome playback, paragraph detection, and highlighting; `make integration-test` checks the live native bridge without playing sound.
